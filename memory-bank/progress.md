# 进度

当前状态、最近完成、下一步与未决问题。只写事实，区分已验证与未验证。

## 当前状态（2026-10-25）

第一步（社区库）的仓库内容已在本地准备好，尚未创建公开仓库。

- `spec/`：格式说明、JSON Schema、114 个合成样例与期望结果、15 个匹配用例、内置 MIX 库（10 条加 1 个变体），与映场仓库 `spec/cheer/` 逐字节相同。
- `lib/cheer.js`：按格式说明 §6 实现的 JavaScript 读取器，无依赖。
- `lib/library.js`、`tools/`：社区规则检查（位置、授权、许可、警告、重复、MIX 库）与 `index.json` 生成。
- `.github/`：“检查”工作流（Pull Request 与推送，只读权限）、“更新索引”工作流（合并后提交 `index.json`）、投稿模板、下架请求表单。
- 文档：README、投稿指南、审核标准、下架规则。
- `cheers/` 暂无投稿。

**已验证（本地，Node.js 22）**：`npm test` 149 项通过——读取器对 114 个样例的结果（有效与否、错误 / 警告集合、能否分享、事件起点、ISRC 归一化）与期望结果全部一致，15 个匹配用例一致；另有与 Swift 读取器逐项核对过的边界用例（不成对的代理项、超出范围的数字、假名浊点、全半角、1582 年历法切换、长括号串的线性拆词）；社区规则测试 13 项；`npm run check` 通过。

**独立审查（2026-10-25，只读审查代理）**：发现并已修复——①测试依赖仓库当前的 `index.json`，会让每个投稿 Pull Request 失败（高）；②检查输出未转义，投稿内容可伪造工作流命令（中）；③CI 运行 Pull Request 自带的检查代码（中，改为从基准分支取检查代码，投稿不得与其他修改混在一起，索引工作流的令牌只交给最后的推送）；④拆词遇长串括号为二次复杂度（中）；⑤`cheers/` 下的符号链接被跟随（中）；⑥只差大小写的文件夹、Windows 保留名、截断后残留空白（中）；⑦歌名比较把假名浊点当附加符去掉，与 Swift 不一致（中）；以及专辑与作者数上限、重复判断忽略署名、MIX 库检查遇非字符串崩溃、多处文档说法（低）。

**未验证**：GitHub 上的工作流运行（需仓库创建后）；“更新索引”工作流的自动提交；网页上的 Issue 表单与 Pull Request 模板显示。
